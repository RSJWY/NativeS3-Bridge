# implement.md 需求可追溯性闸门

> 父任务：`.trellis/tasks/08-16-node-cert-lifecycle`
> 本任务是从父任务根因分析中析出的**流程修复**，与证书功能无关，可与其余子任务并行，无依赖。
> 轻量任务：PRD-only。

## Goal

把「PRD 每条 Requirement 必须能在 `implement.md` 找到对应步骤」固化成 `.trellis/spec` 里的显式检查项，使同类需求蒸发在下一次发生前就被拦住。

## 背景：这次的实证案例

父任务查明的断点（完整表格见父任务 `prd.md` 背景节）：

| 环节 | 位置 | 状态 |
|---|---|---|
| 需求 | `07-13.../prd.md:47,53` 明确要求面板管理证书**续期**生命周期 | ✅ |
| 设计 | `07-13.../design.md:100-103` §3.3 详细设计了续期方案 | ✅ |
| 风险预案 | `07-13.../design.md:216` 依赖「到期前主动续期」 | ✅ |
| **执行清单** | `07-13.../implement.md` 155 行 8 阶段，**全文无「续期」二字** | ❌ 断点 |
| 实现 / check | 无实现；check 对着 implement.md 走 → **全绿** | ⚠️ 假绿 |

两个加剧因素，都值得写进 spec：

1. **规划级 AC 冒充实现级 AC**：该 PRD 的 10 条验收标准（`prd.md:79-88`）全是「明确……流程」句式。流程确实被写进了 design，所以**不实现任何代码即可满足**。全程没有一条 AC 能因「续期没做」而失败。
2. **通过的测试提供虚假安心**：`implement.md:51` 要求覆盖「过期证书被拒」，`pkg/panel/pki_test.go:122` 如实实现且持续通过。风险预案的「拒绝接入」半边被实现并测试，「主动续期」半边不存在——**测试套件在确认坏行为工作正常**。

## Requirements

### R1 追溯闸门检查项
- R1.1 在 `.trellis/spec/guides/` 新增一份思考指南（建议名 `requirement-traceability-guide.md`），核心内容：从 PRD Requirement → implement.md Step 的正向映射自查表。
- R1.2 明确闸门时机：**`task.py start` 之前**（对应 workflow 步骤 1.4 的审查关口）。此时 prd/design/implement 三件齐备，正是做映射核对的唯一时点。
- R1.3 给出可操作的核对动作，而非泛泛原则。至少包含：
  - 逐条读 PRD 的 Requirement 编号，在 implement.md 里找承载它的 Step；找不到即为断点。
  - 反向核对：implement.md 里存在但 PRD 未要求的 Step —— 可能是范围蔓延或 PRD 漏写。
- R1.4 收录本次的实证案例作为反面教材（简短，带 file:line），使指南有可信度而非说教。

### R2 AC 分级约定
- R2.1 在指南中区分**规划级 AC**（「明确/输出/形成……文档」）与**实现级 AC**（「某输入 → 某可观测行为」），并给出判据：**若一条 AC 在零行代码改动下即可满足，它就是规划级 AC，不得计入实现验收**。
- R2.2 约定：任何有代码交付的任务，其 AC 中必须存在至少一条**会因该功能缺失而失败**的实现级 AC。

### R3 虚假安心测试的识别
- R3.1 在指南中加入一条检查：当风险预案由「防御半边 + 补偿半边」组成时（如「过期则拒绝接入 + 到期前主动续期」），只测防御半边会产生虚假安心。要求两半边各自有对应的 Step 与 AC。
- R3.2 与既有 `guides/index.md` 中「tautological test」检查项（`## Quick Reference` 节内）呼应，不重复造轮子——在那条附近交叉引用即可。

### R4 挂载与可发现性
- R4.1 更新 `.trellis/spec/guides/index.md` 的 Available Guides 表格与 Quick Reference 触发清单，加入本指南的入口与触发条件。
- R4.2 语言与既有 guides 保持一致（现为英文），不做语言迁移。

## 约束

- **纯 spec 文档任务**，不得改动任何产品代码、不得改 `.trellis/scripts/`。
- 不新增强制流程环节（AC7）。目标是让人在 1.4 关口多做一次三分钟的映射核对，而非增加仪式。
- 保持 `.trellis/spec/guides/` 既有文件风格（英文、表格 + 勾选清单 + 「Core Principle」收尾）。
- 不批评具体人；案例只陈述事实与 file:line。
